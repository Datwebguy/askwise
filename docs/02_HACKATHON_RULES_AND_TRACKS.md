## 4. Rules to follow

- Teams must have between 1 and 4 members.
- A team can submit up to 2 projects.
- The organisers expect working products.
- The project must be built during the hackathon.
- Existing open-source libraries and APIs are allowed.
- The README must explain what existed before November 23.
- The main integration must use an application listed in the selected track.
- Projects may connect applications from a second track when there is a genuine reason.
- Never commit API keys or private credentials.
- Financial features must use safe test or read-only data. No user funds or financial advice.

## 5. Submission requirements

- Public GitHub or GitLab repository.
- README with setup instructions.
- Demo video of up to 3 minutes.
- Short project description.
- Selected track.
- Optional packaged .ehpk file.
- Up to 5 optional feature requests.

The demo is allowed to use the official simulator. A physical G2 device is not required.

## 6. Judging criteria

| Category | Weight |
|---|---:|
| Usefulness on G2 | 30% |
| Read and write integration | 25% |
| Technical execution | 20% |
| Display and voice experience | 15% |
| Business potential and safety | 10% |

Every major AskWise feature should support one or more of these judging areas.
